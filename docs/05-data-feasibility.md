# PropertyAgent 데이터 소스 실현가능성 조사 보고서

> 작성일: 2026-03-28
> 상태: Critical Risk Assessment
> 목적: 한국 부동산 매물 데이터의 실제 확보 가능성을 조사하고, MVP 데이터 전략을 재정립

---

## Executive Summary

**핵심 결론: 한국에는 "현재 판매 중인 매물" 데이터를 합법적으로 제공하는 공개 API가 존재하지 않는다.**

공공 API(국토부)는 이미 거래가 완료된 실거래가 데이터만 제공하며, 민간 플랫폼(네이버부동산, 직방, 다방)은 공식 API를 외부에 개방하지 않는다. 네이버부동산 비공식 API 크롤링은 2024년 법원 판례(네이버 vs 다윈중개)에서 손해배상 판결이 나왔으므로 사업 목적 활용은 법적 리스크가 매우 높다.

따라서 **MVP 전략을 "매물 알림"에서 "실거래가 기반 가격 인텔리전스"로 피봇하는 것을 강력히 권고**한다.

## 1. 공공 데이터 API 상세 분석

### 1.1 국토교통부 실거래가 공개시스템 API

| 항목 | 내용 |
|------|------|
| **출처** | [공공데이터포털 (data.go.kr)](https://www.data.go.kr/data/15126469/openapi.do) |
| **제공 데이터** | 아파트/연립다세대/단독다가구/오피스텔 매매 및 전월세 실거래 신고 정보 |
| **데이터 항목** | 법정동, 단지명, 전용면적, 거래금액, 계약일, 층, 건축연도, 해제여부 등 |
| **갱신 주기** | 매월 (거래 신고 후 약 1-2개월 후 반영) |
| **접근 방법** | API 키 발급 (무료), REST API |
| **비용** | 무료 |
| **일일 호출 제한** | 1,000회/일 (신청 시 확장 가능) |
| **제공 API 종류** | 11종 (아파트매매, 아파트전월세, 연립다세대매매, 오피스텔매매, 상업용매매 등) |

**핵심 한계:**
- **과거 거래 데이터만 제공**한다. "현재 매물"이 아니라 "이미 계약 완료된 거래"
- 신고 후 반영까지 시간 지연이 있어 실시간성이 떨어진다
- 매물 호가(asking price)가 아닌 실제 거래가(transaction price)

**활용 가능성:**
- 특정 단지/지역의 최근 거래 발생 시 알림 (가격 추이 모니터링)
- 시세 대비 저가/고가 거래 감지
- 지역별 거래량 변동 추적

### 1.2 한국부동산원 부동산통계 Open API

| 항목 | 내용 |
|------|------|
| **출처** | [부동산통계정보시스템 R-ONE](https://www.reb.or.kr/r-one/portal/openapi/openApiIntroPage.do) |
| **제공 데이터** | 전국지가변동률, 전국주택가격동향, 공동주택 실거래가격지수, 상업용부동산 임대동향 |
| **데이터 성격** | 통계/지수 데이터 (개별 매물이 아닌 집계 데이터) |
| **접근 방법** | API 키 발급 (무료), REST API |
| **비용** | 무료 |

**핵심 한계:**
- 개별 매물 정보가 아닌 **통계 지표** (전국/지역 단위 가격지수, 변동률)
- 매물 데이터 제공 없음

**활용 가능성:**
- 지역별 시장 동향 분석 콘텐츠 생성
- "이 지역 가격이 3개월 연속 하락 중" 같은 시장 인사이트 알림

### 1.3 부동산 빅데이터 플랫폼 (REBPP)

| 항목 | 내용 |
|------|------|
| **출처** | [bigdata-realestate.kr](https://www.bigdata-realestate.kr/) |
| **제공 데이터** | 상권 에너지 사용량, 소음지도, 건축물 노후도, 시설 접근성, 분양정보 |
| **데이터 성격** | 부동산 관련 부가 데이터 (매물 데이터 아님) |
| **접근 방법** | 플랫폼 내 조회, 일부 API |
| **비용** | 무료 (일부 유료) |

**핵심 한계:**
- **매물 데이터를 제공하지 않는다**
- 부동산 주변 환경/인프라 데이터에 집중

**활용 가능성:**
- 매물 부가 정보로 활용 (소음, 접근성, 학군 등)
- 지역 분석 리포트 생성

### 1.4 기타 공공 데이터

| 데이터 | 출처 | 활용 가능성 |
|--------|------|------------|
| 건축물대장 | 국토부/data.go.kr | 건물 정보, 면적, 용도, 건축연도 |
| 토지대장/토지이용계획 | 국토부/data.go.kr | 용도지역, 개발 가능성 분석 |
| 주택공시가격 | 국토부/data.go.kr | 공시가격 기반 시세 추정 |

**결론: 공공 데이터에서 "현재 매물" 데이터를 얻는 것은 불가능하다.**

## 2. 민간 데이터 소스 상세 분석

### 2.1 네이버 부동산

| 항목 | 내용 |
|------|------|
| **매물 보유량** | 국내 최대 (중개사 직접 등록) |
| **공식 API** | **없음** (공식 API를 외부에 제공하지 않음) |
| **비공식 API** | 존재 (fin.land.naver.com 등 내부 API 엔드포인트) |
| **크롤링 리스크** | **매우 높음** |

**법적 리스크 상세:**
- **2024년 서울지방법원 판결**: 다윈중개가 네이버부동산 매물 데이터를 크롤링한 사건에서, 법원은 네이버파이낸셜에 **7,000만원 손해배상** 판결을 내렸다
- 법원은 네이버를 **저작권법상 데이터베이스 제작자**로 인정하고, 크롤링이 부정경쟁행위에 해당한다고 판단
- 기술적으로도 IP 차단, rate limiting 등 적극적 차단 조치 시행 중
- [전자신문 보도](https://www.etnews.com/20241007000224)

**판단: 사업 목적 활용 불가. 절대 의존해서는 안 됨.**

### 2.2 직방

| 항목 | 내용 |
|------|------|
| **매물 보유량** | 대형 (중개사 직접 등록 모델) |
| **공식 API** | **없음** (외부 개방 API 미제공) |
| **사업 모델** | 중개사가 직접 매물을 등록하고, 광고비를 지불하는 B2B 모델 |
| **데이터 제휴 가능성** | 극히 낮음 (매물 데이터가 핵심 자산) |

**참고사항:**
- 직방은 원래 원룸/투룸 매물 중심이었으나, 2025년부터 아파트PRO, 아파트BASIC 등 아파트 공인중개사 전용 서비스 확대
- AI 매물 추천 기능 자체 개발 중 (경쟁 서비스에 데이터를 줄 동기 없음)

### 2.3 다방 (스테이션3)

| 항목 | 내용 |

| **데이터 제휴 가능성** | 극히 낮음 |

| 항목 | 내용 |
|------|------|

| 항목 | 내용 |

- 한방 고도화 계획이 있어, 오히려 자체 플랫폼 강화에 집중할 가능성이 높음
- 한국판 MLS(Multiple Listing Service)에 가장 가까운 시스템이나, 참여율과 데이터 품질이 미국 MLS 대비 매우 낮음

- 스타트업 규모에서 유료 API 비용 부담 가능성
- MVP 단계에서 외부 유료 API 의존은 리스크

## 3. 해외 사례 비교 분석

### 3.1 미국: MLS 기반 생태계

| 항목 | 미국 | 한국 |
|------|------|------|
| **중앙 매물 DB** | MLS (Multiple Listing Service) - 약 600개 지역 MLS | **없음** (한방이 유사하나 참여율 극히 낮음) |
| **접근 방식** | 중개사 의무 등록, IDX/RETS 프로토콜로 데이터 공유 | 중개사 자율 등록, 플랫폼별 분산 |
| **데이터 접근** | 브로커리지 라이선스로 MLS 접근 가능 | 플랫폼별 폐쇄적 운영 |
| **법적 프레임워크** | NAR 규정, IDX 정책으로 데이터 공유 의무화 | 매물 데이터 공유 의무 없음 |

### 3.2 Zillow의 데이터 전략

- **초기**: ListHub를 통해 MLS 데이터 일괄 수신
- **현재**: 각 지역 MLS와 개별 데이터 피드 계약 체결 (syndication)
- **보완**: 사용자/에이전트가 직접 입력한 데이터, 카운티 공공 기록
- **핵심 자산**: Zestimate (AI 가격 추정 모델) - 매물 데이터 없이도 가치 제공

### 3.3 Redfin의 데이터 전략

- **핵심 전략**: 자체가 **브로커리지 라이선스** 보유 -> MLS 직접 멤버로서 데이터 접근
- 70%의 신규 매물이 5분 이내 Redfin에 반영
- 자체 에이전트가 현장 데이터를 추가로 입력

### 3.4 한국에 대한 시사점

**미국 모델은 한국에 직접 적용 불가능하다:**
1. 한국에는 의무적 MLS 시스템이 없다
2. 중개사의 매물 공유 문화가 형성되어 있지 않다
3. 네이버부동산/직방/다방이 사실상의 MLS 역할을 하지만, 데이터를 개방하지 않는다
4. 브로커리지 라이선스만으로 매물 데이터에 접근할 수 있는 구조가 아니다

## 4. 선행 성공 사례 분석: 매물 데이터 없이 성공한 서비스

### 4.1 호갱노노

| 항목 | 내용 |
|------|------|
| **MAU** | 179만 (업계 2위) |
| **핵심 데이터** | 국토부 실거래가 API (공공 데이터 13종 활용) |
| **매물 데이터** | 직접 보유하지 않음 |
| **수익 모델** | 광고, 프리미엄 구독 |
| **핵심 가치** | 실거래가 즉시 알림, 시세 추이 시각화, 관심 단지 모니터링 |

**교훈: 매물 데이터 없이도 "실거래가 인텔리전스"만으로 MAU 179만을 달성했다.**

| **매물 데이터** | 없음 |
| **핵심 가치** | 다양한 주거 형태의 실거래가 정보 + 분석 |

### 4.3 부동산플래닛

| 항목 | 내용 |
|------|------|

## 6. MVP 데이터 전략 수정안

### 6.1 전략 피봇: "매물 알림" -> "가격 인텔리전스 알림"

**기존 전략 (위험):**
> 현재 판매 중인 매물을 수집하여, 조건에 맞는 매물이 나오면 알림

**수정 전략 (실현 가능):**
> 공공 데이터 기반으로 실거래가 변동, 시세 추이, 시장 신호를 분석하여 투자/매수 타이밍 알림

### 6.2 MVP 3단계 데이터 전략

#### Phase 1: 공공 데이터 Only (0-3개월, 비용 0원)

**데이터 소스:**
- 국토부 실거래가 API (11종) -- 핵심
- 한국부동산원 통계 API -- 보조
- 건축물대장/토지대장 API -- 보조
- 공시가격 API -- 보조

**제공 가능한 알림:**
1. **실거래가 알림**: "관심 단지에서 새로운 거래가 발생했습니다. OO아파트 84m2, 12억 3000만원 (전월 대비 -2%)"
2. **급매 신호 알림**: "XX동 최근 1주일 거래 3건 발생. 평균 시세 대비 5% 저렴한 거래 포착"
3. **시장 동향 알림**: "관심 지역 강남구, 3개월 연속 거래량 증가 / 가격 보합"
4. **가격대 돌파 알림**: "OO아파트 84m2 실거래가가 처음으로 10억 이하로 내려왔습니다"
5. **전세가율 알림**: "XX단지 전세가율이 70%를 돌파했습니다 (갭투자 관심 신호)"

**호갱노노와의 차별점:**
- 단순 실거래 알림이 아닌 **분석 기반 인사이트** 제공
- AI가 "왜 이 거래가 중요한지" 해석해서 알려줌
- 사용자 맞춤 조건 (예산, 면적, 지역, 투자 목적)에 따른 필터링

#### Phase 2: 유료 데이터 통합 (3-6개월)

**추가 데이터 소스:**
- KB시세 API 연동 (유료 제휴)
- 오키씨 API 검토 (AI시세, 권리분석)

**추가 제공 가능한 알림:**
1. **시세 변동 알림**: "관심 단지 KB시세가 이번 주 500만원 하락했습니다"
2. **시세 vs 실거래 괴리 알림**: "이 단지 실거래가가 KB시세보다 8% 낮습니다 (매수 기회?)"
3. **AI 가격 예측**: "향후 3개월 가격 전망: 보합~소폭 하락 (신뢰도 78%)"

#### Phase 3: 매물 데이터 확보 (6개월 이후, 사업 검증 후)

**방법 A - 중개사 직접 등록 모델:**
- 중개사 전용 앱/웹 개발
- 매물 등록 시 노출 보장 (광고 모델과 연동)
- 직방/다방이 이 모델로 성장했으나, 초기 중개사 확보가 최대 난관

**방법 B - 데이터 제휴:**
- 부동산114, 한방 등과 B2B 데이터 제휴
- 충분한 사용자 기반(MAU)이 확보된 후 협상력 확보

**방법 C - 역발상 (사용자 매물 제보):**
- 사용자가 관심 단지에서 발견한 매물 정보를 직접 제보
- 크라우드소싱 방식으로 매물 DB 구축
- 정확도 검증 이슈가 있으나, 커뮤니티 기반 서비스와 시너지

### 6.3 "매물 데이터 없이 MVP를 시작할 수 있는가?"

**결론: 가능하다. 오히려 더 현실적이다.**

근거:
1. **호갱노노가 증명했다**: 매물 데이터 없이 실거래가만으로 MAU 179만 달성
2. **공공 데이터만으로 충분한 가치를 제공할 수 있다**: 실거래가 발생 알림 + AI 분석 인사이트
3. **매물 데이터 확보 비용 회피**: 초기 스타트업이 매물 DB를 구축하려면 중개사 영업 비용이 막대
4. **법적 리스크 제로**: 공공 API만 사용하므로 크롤링/저작권 이슈 없음
5. **차별화 가능**: 호갱노노는 "데이터 뷰어"에 가깝고, PropertyAgent는 "AI 인사이트 + 맞춤 알림"으로 차별화

## 8. 실행 권고사항

### 즉시 조치 (이번 주)

1. **PRD 수정**: "매물 알림" 기능을 "실거래가 기반 가격 인텔리전스 알림"으로 재정의
2. **공공데이터포털 API 키 발급**: 국토부 실거래가 API 11종 전체 신청
3. **데이터 파이프라인 PoC**: 실거래가 API 호출 -> 데이터 정제 -> Supabase 저장 프로토타입

### 단기 (1-2주)

4. **오키씨(OKYC) API 상세 조사**: 매물 데이터 제공 여부, 가격, API 스펙 직접 문의
5. **KB부동산 데이터허브 B2B 제휴 문의**: 시세 데이터 API 비용 및 조건 확인
6. **경쟁사 분석 심화**: 호갱노노의 알림 기능 UX를 상세 분석하여 차별점 설계

### 중기 (1-3개월)

7. **MVP 출시**: 공공 데이터 기반 가격 인텔리전스 알림 서비스
8. **사용자 검증**: "매물 알림이 없어도 이 서비스를 쓰겠는가?" 직접 확인
9. **데이터 전략 재평가**: 사용자 피드백 기반으로 Phase 2 진입 여부 결정
