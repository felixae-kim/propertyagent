## 1. Overview

PropertyAgent는 "원하는 아파트, 원하는 가격에 나올 때 알려드립니다"라는 핵심 가치를 가진 부동산 매물 알림 및 탐색 서비스이다. 비상업 개인 프로젝트로, 본인과 주변 지인들의 실제 니즈를 해결하기 위해 개발한다.

기존 부동산 앱들이 "사용자가 직접 매물을 찾아야 하는" 능동 검색 패러다임에 머무는 반면, PropertyAgent는 "주식 지정가 주문"이라는 멘탈 모델을 부동산에 적용하여 조건 설정 후 매물이 사용자를 찾아오는 수동 알림 패러다임을 구현한다.

**데이터 전략**: 3-Layer 구조로 데이터를 수집한다.
- **Layer 1 (Foundation)**: 국토부 실거래가 공공 API — 합법, 무료, 시세 기준선
- **Layer 2 (Primary)**: 네이버부동산 비공식 API 크롤링 — 현재 매물 데이터 (개인용 소규모, 비상업)
- **Layer 3 (Supplement)**: 직방 비공식 API — 원룸/빌라/오피스텔 보조 소스

크롤링 차단 시 자동으로 공공 API 기반 "실거래가 인텔리전스" 모드로 fallback 가능한 구조로 설계한다.

## 2. Goals & Non-Goals

### Goals

| # | 목표 | 연결 지표 |
|---|------|----------|
| G1 | 지정가 매물 알림이라는 새로운 카테고리를 시장에 도입하여 1차 타겟 사용자(매수 대기자)의 핵심 Pain Point를 해결한다 | 알림 설정 완료율 > 60% |
| G2 | 커머스형 직관적 UX로 부동산 탐색의 진입 장벽을 낮춘다 | 온보딩 완료율 > 70% |
| G3 | 8주 내 MVP를 출시하여 본인 및 지인(10-20명) 대상으로 실사용 검증한다 | 실사용자 피드백, 알림 유용성 확인 |
| G4 | 알림을 통한 매물 확인 경험으로 높은 리텐션을 확보한다 | 알림 클릭률 > 30%, 월 리텐션 > 40% |

### Non-Goals

| # | 비목표 | 이유 |
|---|--------|------|
| NG1 | 매물 중개 또는 거래 기능 제공 | 정보 제공과 알림에 집중. 중개 기능은 비상업 프로젝트 범위 밖 |
| NG2 | 복합 조건 알림 (지역+세대수+학군+금액 조합) | 조건 매칭 엔진 복잡도가 높아 Phase 2로 연기. MVP는 단지+가격 조건에 집중 |
| NG3 | 인플루언서/전문가 추천 큐레이션 | 콘텐츠 큐레이션 운영 비용이 높아 Phase 2 이후 |
| NG4 | 네이티브 앱 (iOS/Android) | MVP는 웹(PWA) 기반 |
| NG5 | 전국 단위 서비스 | MVP는 수도권 주요 단지 중심. 크롤링 부하 최소화 |
| NG6 | AI 가격 예측 | 데이터 축적 후 장기 로드맵에서 검토 |
| NG7 | 수익화/상업화 | 개인 프로젝트로 수익 목적 없음. 프리미엄 구독 등 불필요 |

## 4. User Stories

### US-1: 소셜 로그인으로 빠르게 가입하기 (F1)

**Priority**: P0 (Must-have)

```
As a 부동산 매물 탐색자,
I want to 소셜 계정(Google, Kakao)으로 3초 내에 가입하고 싶다,
So that 복잡한 가입 절차 없이 바로 알림 설정을 시작할 수 있다.
```

### US-2: 관심 단지 등록하기 (F2)

**Priority**: P0 (Must-have)

```
As a 아파트 매수를 고려하는 사용자,
I want to 검색으로 찾은 아파트 단지를 관심 등록하고 싶다,
So that 해당 단지의 매물 변동을 추적할 수 있다.
```

### US-3: 지정가 알림 설정하기 (F3)

**Priority**: P0 (Must-have)

```
As a 특정 아파트를 목표가에 매수하고 싶은 사용자,
I want to 관심 단지에 희망 매매가를 설정해두고 싶다,
So that 해당 가격 이하 매물이 등장하면 즉시 알림을 받아 놓치지 않을 수 있다.
```

### US-4: 매물을 카드형 UI로 탐색하기 (F5)

**Priority**: P0 (Must-have)

```
As a 부동산 정보를 쉽게 탐색하고 싶은 사용자,
I want to 매물 정보를 쇼핑몰 상품 카드처럼 직관적으로 보고 싶다,
So that 복잡한 표나 목록 없이도 매물을 빠르게 비교하고 판단할 수 있다.
```

### US-5: 매물 상세 정보 확인하기 (F6)

**Priority**: P0 (Must-have)

```
As a 특정 매물에 관심이 생긴 사용자,
I want to 매물의 실거래가 이력, 단지 정보, 주변 시설을 한 화면에서 보고 싶다,
So that 추가 검색 없이 매수 여부를 판단할 수 있다.
```

### US-6: 교통 호재를 지도에서 확인하기 (F7)

**Priority**: P1 (Should-have)

```
As a 교통 호재 기반으로 투자를 검토하는 사용자,
I want to GTX, 신분당선 등 교통 개발 호재의 정확한 역 위치를 지도에서 보고 싶다,
So that 호재의 실제 수혜 범위를 직관적으로 파악하여 투자 판단에 활용할 수 있다.
```

### US-7: 관심 매물 저장하기 (F8)

**Priority**: P0 (Must-have)

```
As a 여러 매물을 비교 검토하는 사용자,
I want to 마음에 드는 매물이나 단지를 찜 목록에 저장하고 싶다,
So that 나중에 다시 찾아보거나 비교할 때 편리하다.
```

### US-8: 브라우저를 닫아도 알림 받기 (F9)

**Priority**: P0 (Must-have)

```
As a 지정가 알림을 설정한 사용자,
I want to 브라우저를 닫아도 매칭 매물 알림을 푸시로 받고 싶다,
So that 앱에 접속하지 않아도 중요한 매물을 놓치지 않는다.
```

### US-9: 가입 직후 빠르게 조건 설정하기 (F10)

**Priority**: P1 (Should-have)

```
As a 처음 서비스를 사용하는 사용자,
I want to 3단계 이내의 간단한 온보딩으로 관심 조건을 설정하고 싶다,
So that 가입 직후 바로 알림을 받을 수 있는 상태가 된다.
```

### US-10: 알림 내역 확인하기

**Priority**: P0 (Must-have)

```
As a 알림을 받은 사용자,
I want to 지금까지 받은 알림 목록을 한 곳에서 확인하고 싶다,
So that 놓친 알림도 나중에 다시 확인할 수 있다.
```

## 5. Detailed Requirements

### 5.1 F1: 회원가입/로그인 (Authentication)

**관련 User Story**: US-1

#### 5.1.1 기능 요구사항 (Functional Requirements)

| # | 요구사항 | 설명 |
|---|---------|------|
| FR-1.1 | 소셜 로그인 지원 | Google, Kakao 계정을 통한 OAuth 2.0 로그인을 제공한다 |
| FR-1.2 | 비로그인 탐색 허용 | 로그인 없이도 매물 카드 탐색, 교통 호재 지도 조회가 가능하다. 알림 설정, 관심 목록 저장 시 로그인을 요구한다 |
| FR-1.3 | 세션 유지 | 로그인 후 30일간 세션을 유지한다 (Refresh Token) |
| FR-1.4 | 회원 탈퇴 | 설정 화면에서 회원 탈퇴가 가능하며, 탈퇴 시 모든 개인 데이터(알림 조건, 관심 목록, 알림 이력)가 삭제된다 |

#### 5.1.2 수용 기준 (Acceptance Criteria)

| # | Given | When | Then |
|---|-------|------|------|
| AC-1.1 | 미로그인 상태의 사용자가 서비스에 접속했을 때 | 로그인 버튼을 탭하면 | Google과 Kakao 로그인 옵션이 표시되고, 선택한 소셜 계정으로 인증이 완료되며, 3초 이내에 메인 화면으로 이동한다 |
| AC-1.2 | 미로그인 사용자가 매물 카드를 탐색 중일 때 | 관심 목록 저장 버튼을 탭하면 | 로그인 유도 바텀시트(Bottom Sheet)가 나타나고, 로그인 완료 후 해당 매물이 자동으로 관심 목록에 추가된다 |
| AC-1.3 | 로그인된 사용자가 브라우저를 닫고 30일 이내에 재접속할 때 | 서비스 URL에 접속하면 | 별도 로그인 없이 자동으로 로그인 상태가 유지된다 |
| AC-1.4 | 로그인된 사용자가 회원 탈퇴를 요청할 때 | 설정 > 회원 탈퇴를 탭하고 확인하면 | 모든 개인 데이터가 삭제되고, 로그아웃 처리되며, 서비스 메인 화면으로 이동한다 |

#### 5.1.3 엣지 케이스 (Edge Cases)

| # | 상황 | 처리 방법 |
|---|------|----------|
| EC-1.1 | 소셜 로그인 제공자(Google/Kakao) 서버 장애 | "로그인 서비스에 일시적인 문제가 있어요. 잠시 후 다시 시도해주세요" 메시지 표시. 다른 소셜 로그인 옵션 안내 |
| EC-1.2 | 동일 이메일로 다른 소셜 계정 가입 시도 | "이미 [Google/Kakao] 계정으로 가입되어 있어요. 해당 계정으로 로그인해주세요" 안내 |
| EC-1.3 | 네트워크 연결 끊김 상태에서 로그인 시도 | "인터넷 연결을 확인해주세요" 메시지 표시 |
| EC-1.4 | Refresh Token 만료 (30일 경과) | 자동으로 로그인 화면으로 이동하고, 재로그인 유도 |

#### 5.1.4 비즈니스 규칙 (Business Rules)

- BR-1.1: 이메일 주소가 사용자 고유 식별자로 사용된다 (동일 이메일 = 동일 사용자)
- BR-1.2: 회원 탈퇴 후 동일 이메일로 재가입이 가능하나, 이전 데이터는 복구되지 않는다
- BR-1.3: 개인정보 수집 동의는 최초 가입 시 1회 수행한다 (이메일, 서비스 이용 기록)

### 5.2 F2: 관심 단지 등록 (Complex Registration)

**관련 User Story**: US-2

#### 5.2.1 기능 요구사항

| # | 요구사항 | 설명 |
|---|---------|------|
| FR-2.1 | 단지 검색 | 아파트 단지명 또는 주소로 검색하여 단지를 찾을 수 있다 |
| FR-2.2 | 관심 단지 등록 | 검색 결과에서 단지를 선택하여 관심 단지로 등록할 수 있다 |
| FR-2.3 | 관심 단지 해제 | 등록된 관심 단지를 해제할 수 있다 |
| FR-2.4 | 관심 단지 목록 조회 | 등록한 관심 단지 목록을 한 곳에서 확인할 수 있다 |
| FR-2.5 | 관심 단지 수 제한 | 사용자당 최대 50개 단지까지 관심 등록할 수 있다 (크롤링 부하 상한) |

#### 5.2.2 수용 기준

| # | Given | When | Then |
|---|-------|------|------|
| AC-2.1 | 로그인된 사용자가 단지 검색 화면에 있을 때 | "래미안"을 입력하면 | 0.5초 이내에 "래미안"이 포함된 단지 목록이 자동완성(autocomplete)으로 표시된다 |
| AC-2.2 | 검색 결과 목록에서 | 특정 단지의 관심 등록 버튼을 탭하면 | 해당 단지가 관심 목록에 추가되고, 버튼 상태가 "등록됨"으로 변경되며, 등록 완료 피드백이 표시된다 |
| AC-2.3 | 관심 단지가 50개 등록된 상태에서 | 새로운 단지를 관심 등록하려 하면 | "관심 단지는 최대 50개까지 등록할 수 있어요. 기존 단지를 해제하면 새로 등록할 수 있어요" 안내가 표시된다 |
| AC-2.4 | 관심 단지 목록 화면에서 | 특정 단지를 해제하면 | 해당 단지가 목록에서 제거되고, 해당 단지에 설정된 지정가 알림도 함께 비활성화된다 |

#### 5.2.3 엣지 케이스

| # | 상황 | 처리 방법 |
|---|------|----------|

| EC-7.4 | Kakao Maps API 로드 실패 | "지도를 불러오지 못했어요. 새로고침 해주세요" + 새로고침 버튼 |

#### 5.6.4 비즈니스 규칙

- BR-7.1: MVP에서는 수도권 주요 5개 노선(GTX-A, GTX-B, GTX-C, 신분당선 연장, 9호선 연장)만 제공한다
- BR-7.2: 교통 호재 데이터는 관리자가 수동으로 입력/업데이트한다 (주 1회 이상)
- BR-7.3: 역 좌표는 공식 계획 문서 또는 국토교통부 자료 기반으로 입력한다

#### 5.8.3 엣지 케이스

| # | 상황 | 처리 방법 |
|---|------|----------|
| EC-9.1 | 사용자가 브라우저 푸시 권한을 거부한 경우 | 알림 설정 화면에 "알림이 꺼져 있어요. 브라우저 설정에서 알림을 허용해주세요"라는 안내와 설정 방법 가이드 제공 |

- BR-9.3: 알림 이력은 최근 90일간 보관한다

## 6. User Flows

### 6.1 핵심 플로우: 지정가 알림 설정 및 매물 알림 수신 (Happy Path)

```
Step 1: 사용자가 서비스에 접속한다 -> 메인 화면(매물 카드 목록) 표시
Step 2: 사용자가 소셜 로그인(Google/Kakao)으로 가입한다 -> 온보딩 시작
Step 3: 온보딩 Step 1 - 관심 지역 선택(예: "경기도 성남시 분당구")
Step 4: 온보딩 Step 2 - 예산 범위 설정(예: "7억-9억")
Step 5: 온보딩 Step 3 - 중요 조건 태그 선택(예: "초품아", "대단지")
Step 6: 온보딩 완료 -> 추천 단지에 대한 알림 자동 생성 -> 메인 화면 이동
Step 7: 사용자가 단지 검색에서 "래미안 블레스티지"를 검색하여 관심 등록
Step 8: 관심 단지 상세에서 "지정가 알림 설정" 탭
Step 9: 평형 선택(34평) -> 지정가 입력(9억) -> 확인
Step 10: "래미안 블레스티지 34평, 9억 이하 매물이 나오면 알려드릴게요" 확인
Step 11: 브라우저 푸시 알림 허용 요청 -> 허용
Step 12: [시간 경과 - 매물 수집 Cron 실행]
Step 13: 래미안 블레스티지 34평, 8.7억 매물이 수집됨
Step 14: 알림 매칭 엔진이 해당 매물을 사용자 조건과 매칭
Step 15: Web Push 발송: "래미안 블레스티지 새 매물 - 34평 8.7억 매물이 등록됐어요"
Step 16: 사용자가 푸시 알림 탭 -> 매물 상세 페이지로 이동
Step 17: 실거래가 이력, 단지 정보, 주변 시설 확인
Step 18: 관심 목록에 저장 또는 원본 매물 링크로 이동
```

### 6.2 에러 플로우: 푸시 알림 권한 거부

```
Step 1-10: Happy Path와 동일
Step 11: 브라우저 푸시 알림 허용 요청 -> 거부
Step 12: 알림 설정 화면에 "알림이 꺼져 있어요" 안내 배너 표시
Step 13: 대안 안내: "브라우저 설정에서 알림을 허용하거나, 이메일로 알림을 받을 수 있어요"
Step 14: 이메일 알림 옵션 활성화 (fallback)
```

### 6.3 빈 상태 플로우: 첫 방문 사용자 (비로그인)

```
Step 1: 사용자가 서비스에 접속한다 -> 매물 카드 목록 표시 (비로그인)
Step 2: 매물 카드를 스크롤하며 탐색
Step 3: 관심 있는 매물 카드의 찜 아이콘 탭
Step 4: 로그인 유도 바텀시트 표시: "관심 매물을 저장하려면 로그인이 필요해요"
Step 5-a: 로그인 진행 -> 해당 매물 자동으로 관심 목록에 추가
Step 5-b: "나중에" 선택 -> 바텀시트 닫힘, 계속 비로그인 탐색
```

### 6.4 로딩 상태

| 화면 | 로딩 상태 처리 |
|------|--------------|
| 매물 카드 목록 | 카드 형태의 스켈레톤 UI(Skeleton Screen) 표시 |
| 매물 상세 페이지 | 섹션별 스켈레톤 UI 표시 (기본 정보 -> 차트 -> 지도 순서로 점진적 로드) |
| 교통 호재 지도 | 지도 로드 중 로딩 스피너(Spinner) 표시 |
| 알림 목록 | 리스트형 스켈레톤 UI 표시 |

### 7.3 크롤링 차단 방지 전략

| 항목 | 설정값 |
|-----|--------|
| 요청 간격 | 2~5초 (랜덤 jitter) |
| 시간당 최대 요청 | 200~300회 |
| User-Agent | 실제 브라우저 UA 3~5개 로테이션 |
| 차단 감지 | HTTP 403/429, 빈 응답 감지 |
| 차단 시 대응 | 30분 backoff → 연속 3회시 6시간 차단 → 관리자 알림 |
| Fallback | 크롤링 차단 시 공공 API 기반 "실거래가 인텔리전스" 모드로 자동 전환 |

### 7.4 DB 스키마 요약

| 테이블 | 설명 | 주요 필드 |
|--------|------|----------|

| complexes | 아파트 단지 마스터 | complex_no(PK), complex_name, address, lat/lng, total_household, pyeong_details(JSONB) |

### 7.5 데이터 검증 규칙 (Validation Rules)

| 필드 | 규칙 |
|------|------|
| user_conditions.price_max | >= 1,000 (만원), 정수 |
| raw_naver_articles.price_text | 빈 문자열 허용 (가격 문의) |
| complexes.latitude/longitude | 대한민국 범위 내 (lat: 33-43, lng: 124-132) |
| user_profiles.email | 유효한 이메일 형식 |
| user_conditions per user | 최대 20개 |
| watched_complexes per user | 최대 50개 (크롤링 부하 상한) |

### 7.6 Fallback 전략

```
[Primary] 네이버 + 직방 매물 크롤링
     |

     v
[Fallback 1] 국토부 실거래가 Only 모드

```

## 10. Design Notes

### 10.1 핵심 UX 원칙 (토스 디자인 원칙 기반)

| 원칙 | 적용 방법 |
|------|----------|
| 한 화면, 한 목적 | 매물 목록, 알림 설정, 교통 지도를 각각 독립된 화면으로 구성. 하나의 화면에서 여러 작업을 요구하지 않는다 |

| 즉각적 피드백 | 관심 등록, 알림 설정, 필터 적용 시 즉시 시각적/촉각적(haptic) 피드백 제공 |
